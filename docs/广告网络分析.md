# 番茄小说 iOS 7.4.3 广告网络全量分析与去广告方案

- 样本：`番茄小说_7.4.3_净化_液态@巨魔商店.ipa`（302.8 MB，包名 `com.dragon.read`，Build 7.4.3，MinimumOS 15.0.1）
- 主二进制：`Payload/Reading.app/Reading`，511,603,408 字节，**未加密**（FairPlay cryptid 已剥离，TrollStore 版），可直接静态分析
- 静态提取：全量可打印字符串 1,920,551 条 → 候选 host 25,061 → 有效公网域名 922 个 → 广告相关命中 3854 条
- 补充样本：`Frameworks/fanqiefn.dylib`（3.28 MB，字符串已混淆/加密，无有效域名）、`LoadControl.dylib`（ellekit 注入器 + 第三方插件，无广告域）、`FanqieX-1.6.2.dylib`（HTML 注入插件，白名单仅 `.fqnovel.com/.fanqienovel.com/.fanqiesdk.com`）
- 关键配置：`tnc.json`（TTNet 网络配置）直接给出广告集群域名；`Info.plist` 的 `NSAllowsArbitraryLoads=true`，全量 HTTP 放行，抓包无 ATS 障碍

## 一、结论先行

番茄小说 iOS 端**没有外挂第三方广告 SDK 域名**（无 pangle.io / gdt.qq.com / kwai / Sigmob / Mintegral / AppLovin 任何痕迹），广告体系是字节自研 `BDADSDK` + `BDMannor*`（穿山甲内核，CSJ）自建接入，全部流量落在自家域名，分三张网：

| 网络 | 域名族 | 作用 |
|---|---|---|
| ① 广告专用集群 | `ads.zijieapi.com`、`ads3-normal{,-hl,-lf,-lq}.zijieapi.com`、`ads5-normal{,-hl,-lf,-lq}.zijieapi.com`、`ad.zijieapi.com` | 拉广告、上报、激励结算。**只走广告，不承载正文** —— 最干净的一刀 |
| ② 混合主 API | `api{,3,5}-normal*.fqnovel.com`、`reading{,-hl,-lq}.snssdk.com`、`ib/i/is/ic.snssdk.com` | 正文与广告同域，只能在 **路径层** 拦 `/api/ad/` |
| ③ 落地与埋点 | `ad-experience.bytedance.com`、`www.chengzijianzhan.com`、`lf3-analytics.bytescm.com`、`ma/leads`（归因） | 开屏互动页、广告主落地页、广告 JSSDK 埋点 |

> 域名形态说明：二进制里大量出现的 `2freading.snssdk.com`、`2flf-dy-sourcecdn-tos.bytegecko.com` 不是真实主机，`2f` 是 `%2F` 的转义前缀，真实 host 分别是 `reading.snssdk.com` 与 `lf-dy-sourcecdn-tos.bytegecko.com`。这一点不做还原会把域名清单算错一倍。

### 实测说明（重要）

本机所有 DNS 均被代理 TUN 接管，`Resolve-DnsName -Server 223.5.5.5` 与系统默认解析**都返回 `198.18.0.x`（fake-ip 网段）**，因此 DNS 层拿不到真实 A 记录。改用**握手 + 响应**验证，穿透代理出口打到真实上游：

- TLS 1.3 握手成功并返回业务状态码（`200 OK` / `404 Not Found` / `301`）→ 域名真实存在、服务在线、可被 MITM
- `ad.zijieapi.com`、`ib.snssdk.com`、`mon.zijieapi.com`、`polaris.zijieapi.com` 出现 `SSL: UNEXPECTED_EOF`：该会话被上游或本地代理规则直接掐断（本机代理策略已对 `ad.zijieapi.com` 类域做 REJECT），**不代表域名不存在** —— 反而是它已被广泛当作广告域的证据
- `api5-normal-sinfonlinea.fqnovel.com` 返回 `502`：新加坡线路对境内直连做了源限制，属正常

## 四、广告链路是怎么跑起来的

1. **冷启动开屏**：`reading.snssdk.com` 拉 `/api/ad/splash/novelapp/v15/` → 命中则并行 `/api/ad/splash/stock/realtime/v15/` 查库存、`/api/ad/preload_ad/v3/`（`ib.snssdk.com`）预加载素材 → 展示后 `/api/ad/splash/stat/ack/v1/`、`/api/ad/v2/ack/splash/` 回执。二进制里对应的日志原文：`SplashAd request success, source:Brand`、`Ad Close:splash ad not availble, see abtest ad_available_config_v325`
2. **阅读页插页**：正文接口返回的 cell 里混入广告位，`BDADBackPatchAdService`（贴片）判断 `shouldRequestAdWithPlaybackTime:duration:context:`；章末走 `/reading/commerceapi/ad/comment/v1/` 与 `/reading/commerceapi/ad/mix_game/v1/`
3. **激励视频**：`/api/ad/v1/inspire/` 取任务 → 穿山甲内核 `BDMannorUnionRewardedAdLoadDelegate` 拉 `/api/ad/union/sdk/get_ads/` → 完播 `/api/ad/v1/inspire_send/` + `/luckycat/novel/v1/task/done/excitation_ad_*` 发奖
4. **曝光回收**：`/api/ad/v1/report/`、`/aweme/open/export_sdk/report_ad_cpm`、`lf3-analytics.bytescm.com/obj/adjssdk/` 的 external JSSDK

## 五、注意事项（别拦错）

| 对象 | 拦了会怎样 |
|---|---|
| `polaris.zijieapi.com` | 是全站 AB/配置下发，含「免广告特权」判定，拦了功能异常 |
| `security.zijieapi.com` | 风控上传，拦了可能触发登录风控 |
| `mon/log/rtlog.zijieapi.com` | 通用埋点，与广告共用通道，拦了影响阅读时长统计 |
| `/luckycat/novel/v1/privilege/ad_free` | 这是「已开通免广告」的状态查询，拦截会导致你自己买的免广告不生效 |
| 素材 CDN `lf-*.bytegecko.com`、`byteimg.com`、`fqnovelpic.com` | 广告素材与**正文封面共用**，整域拦会把书封和插图一起干掉 |

## 八、怎么复核（App 更新后自己重跑一遍）

```bash
# 1. 解包新版本 ipa
python -c "import zipfile;zipfile.ZipFile('新版本.ipa').extractall('unpacked')"

# 2. 全量字符串落盘
python -c "import re;d=open('unpacked/Payload/Reading.app/Reading','rb').read();open('s.txt','w').write('\n'.join(m.group().decode('utf8','ignore') for m in re.finditer(rb'[ -~]{6,}',d)))"

# 3. 找广告接口
grep -oE '/(api/ad|reading/[a-z]+/ad)[A-Za-z0-9_/%:@.-]*' s.txt | sort -u

# 4. 找广告集群域名（这一步最容易被忽略，域名在 tnc.json 里）
grep -oE '[a-z0-9-]+\.(zijieapi|snssdk|fqnovel)\.com' unpacked/Payload/Reading.app/tnc.json | sort -u
```

线上确认：Quantumult X → 分析 → 活跃连接，过滤关键字 `zijeapi`/`/api/ad/`；开屏时若还能看到 `reading.snssdk.com/api/ad/splash/novelapp/v15/` 存活，说明 MITM 没生效（证书没装、或请求走了 QUIC，见 conf 第【5】段）。

## 九、证书校验评估（决定 MITM 能不能成）

二进制里确实有 pin 机制，但**不在广告链路上**：

| 证据字符串 | 含义 | 挂载位置 |
|---|---|---|
| `setPinnedPublicKeys:` / `pinnedPublicKeys` / `keyPathsForValuesAffectingPinnedPublicKeys` | 公钥 pin（HPKP 风格） | `IESLiveVerifyCertificationModel`、`IESLiveSaaSVerifyCertificationModel` —— 直播 SaaS / 交易模块 |
| `isNeedVerifyLive` | 直播流校验开关 | 同上 |
| `tmp_enable_ssl_verify_peer` / `verify_ssl_with_header_host` | TTNet 按 header host 做 SSL 校验 | TTNet 网络层，默认关闭（`tmp_` 前缀即临时开关） |

结论：pin 只挂在 `webcast.*` 直播域，`api*.fqnovel.com` / `reading*.snssdk.com` / `ad*.zijieapi.com` 上**没有强制 pin 证据**，QX MITM 可行。

稳妥起见按 conf 里的顺序上：先 A 档（只拦广告专用集群，零风险）→ 观察一天 → 再开 C 档（MITM 主 API，按路径拦 `/api/ad/`）。若开了 C 档后 App 提示网络异常或一直转圈，说明该校验在你这台机器的系统版本上被启用了，退回 A 档即可，主体开屏广告仍被 A 档拦掉大半。
